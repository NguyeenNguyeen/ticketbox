# TicketBox Frontend - Current Project State

## Current Phase
**Phase 11: Backend & Connection Integration** — ✅ COMPLETED

## Project Status
The frontend application is fully integrated with the Spring Boot backend REST API. Mock authentication, mock registration, static concert loading, hardcoded checkout redirect, and static E-ticket codes have been completely replaced with real backend API calls. The production build compiles successfully.

## Architecture Status

### Technology Stack (Implemented & Connected)
- **Framework**: Next.js 16.2.7 (App Router) + TypeScript
- **Styling**: Tailwind CSS v4 with custom design system (light theme)
- **State**: Zustand (stores updated: `useAuthStore` connected to `/api/auth/login`, `useSeatStore` dynamically mapping DB categories to interactive SVG seats, `useCartStore` managing purchase idempotency keys)
- **Data & APIs**: Real REST integration via native `fetch` calling Spring Boot backend controllers (CORS permitted, jwt claims containing roles and metadata decoded client-side)
- **QR Code**: qrcode.react (rendering the real ticket UUID generated by the backend factory)
- **Forms**: react-hook-form + zod v4 (login/register/concert forms)

### Existing Implementations
1. **Design System** — globals.css with HSL variables, animations, seat map styles
2. **Types** — concert.ts, seat.ts, order.ts, user.ts
3. **Foundation** — utils, constants, auth, api, backend integration mapping
4. **Stores** — useAuthStore, useSeatStore, useCartStore (updated for API)
5. **Hooks** — useCountdown, useIdempotencyKey, useSSE
6. **UI Components** — Button, Card, Badge, Input, Dialog, Toast, Skeleton
7. **Layout** — Header, Footer, AdminSidebar
8. **Features** — ConcertCard, ConcertGrid, ConcertInfo, SeatMap, Seat, ZoneLegend, OrderSummary, CountdownTimer, PaymentMethodSelector, CheckoutForm, ETicket, StatsCards, RevenueChart, ConcertForm
9. **Pages** — 11 routes total (all successfully connected to API or dynamic parameters)
10. **Security** — middleware.ts protecting /admin routes via JWT cookies, claims validation

### Missing Implementations
- Real SSE server connection (hook is ready, awaits backend event stream deployment)
- Image uploads for concert banners (currently mapped dynamically by title fallback)
- E2E test suite (Playwright / Cypress)
